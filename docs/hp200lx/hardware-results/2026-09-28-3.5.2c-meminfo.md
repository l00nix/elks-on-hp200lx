# Release 3.5.2c: full task-stack measurement confirmed

28 September 2026. Evidence: user photograph `25824.jpg`, supplied after the
3.5.2c handoff. It shows meminfo, four HPST lines and a shell prompt. No boot
banner/HPBOOT line is visible. No screen-speed or control-test report accompanied
this photograph, so the 3.5.2b speed improvement is not assumed for this run.

| Measurement | Task kernel stack | Shared interrupt stack |
| --- | ---: | ---: |
| Measured calls (`n`) | 8 | 148 |
| Total valid calls | 8 | 4,735 |
| Written peak (`used`) | 82 / 700 bytes | 222 / 1,024 bytes |
| ROM-region written peak (`rom`) | 48 bytes | 132 bytes |
| Sticky guard flags | 0 | 0 |

`sample=all/32 guard=each`, with `unknown=0`. Task measurements equal task
calls (8/8), confirming the new every-task-call mode in this run. Shared
sampling remains consistent with measuring call 1 then every 32nd: 4,735 valid
calls yield 148 samples. Both paths have recorded measurements, and no guard
corruption or rejected bounds are reported.

Memory summary: **Main 79/455K used, 376K free; XMS 0/0K used, 0K free**.
These displayed figures match the previous photo's summary; this is not a
controlled allocator or memory-saving comparison.

The peaks match photo 25823 (3.5.2b), with eight task measurements rather than
one. That improves coverage but eight observed task calls remain a small sample
of possible firmware conditions and workloads. Shared depths are still sampled.
Written watermarks miss untouched allocations, marker-value writes and firmware
using another SS. Guard checks cannot catch every overwrite. Neither a zero
guard nor these peaks establishes worst-case safety or justifies smaller stacks.

The next useful result is a longer run on this same build: normal controls and
file reads, then a CPU-bound user loop with keyboard/zoom activity, Ctrl-C and
another meminfo photo. Growing task counters would demonstrate coverage of that
workload. If guard/unknown becomes nonzero, photograph and return to the working
fallback before further stress. Screen speed and keyboard/zoom/panning behavior
for 3.5.2c remain awaiting explicit user confirmation.

This update records observations only. Kernel, helpers, release tag and ZIPs
remain unchanged, with their original build-time notes. 3.5.2c remains a
diagnostic prerelease; stable 3.5 is unchanged.
