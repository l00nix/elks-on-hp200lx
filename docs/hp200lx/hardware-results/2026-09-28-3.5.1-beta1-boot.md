# Release 3.5.1 beta 1: first hardware boot

28 September 2026. Evidence: user-supplied photograph 25811.jpg.

The photograph shows:

- The DOS loader passes its copy/jump handoff and enters ELKS.
- The `HPR351B1 ROM` beta identifier.
- No kernel `rd: 0K ramdisk ...` initialization line.
- CF drive and partition detection, followed by `VFS: Mounted root device /dev/cfa1 (0501) minix filesystem.`
- The shell `#` prompt.
- Kernel sizes consistent with the no-RAMdisk build: 38,784 bytes text, 12,624 far text, 5,184 data and 4,432 BSS.
- The loader still reports `ROOTEND=8C00`, as expected with the unchanged loader and `ROOT092`.

Together with the generated configuration, object list and symbol-map checks,
this confirms that the kernel can boot from CF with RAMdisk support compiled
out on the tested HP 200LX. It passes the copy/jump stage where earlier
MEMLAB6/7 attempts stopped; the root cause of those historical failures remains
unproven.

The screen reports an unchecked Minix filesystem. This successful mount is not
a filesystem-integrity or write-endurance result. The photo shows no typed
commands, so it does not establish keyboard input, zoom/panning, `meminfo`, timer
accuracy or repeated-boot reliability for this beta.

## Follow-up functional test

Later on 28 September, the user reported that `ls /`, `cat /etc/issue` and
`meminfo` all work, and that zoom and panning also work. This confirms basic
keyboard input and external command execution, CF-root directory/file reads,
and the display controls on this beta. `meminfo` runs, but its actual figures
have not yet been supplied; the user will provide a screenshot later.

Still pending: recorded memory figures, modifier/repeat and Ctrl-C checks,
externally measured timer accuracy, sustained writes, repeated-boot testing,
RTC setup and shutdown/suspend/power behavior.

## Known limitation: DOS-style ON/OFF

The user reports that ON/OFF does not work as it does under DOS. This matches
an existing implementation limitation: the HP keyboard path explicitly drops
scan code `0x70` with the comment "ON: no suspend in this beta". That handling
is also present in Release 3.5; it was not introduced by removing the RAMdisk.
Firmware keyboard reuse does not by itself provide DOS-style suspend/resume.
Power management remains a separate follow-up; this report does not establish
which additional firmware/power paths will be required. No binary was changed.

Retain Release 3.5 as the fallback. No kernel, boot helper, release ZIP or tag is
changed by this documentation update.
